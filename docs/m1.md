# TraceSearch-R1 M1

M1 is split into four boundaries:

- **M1-A**: learned-policy substrate, strict action protocol, retriever
  boundary, reward and framework-neutral GRPO objective.
- **M1-B**: training-ready exact rollout provenance, aligned old log-probability
  and token masks.
- **M1-C**: external rLLM/verl trainer integration and optimizer update. It is
  not enabled in this checkout.
- **M1-D**: controlled experimental comparison and reported training results.

The three-row fixture and the local Qwen smoke are plumbing checks, not an NQ
benchmark and not a GRPO training result.

## Learned text policy

`LLMPolicy` uses `ModelClient` and either an OpenAI-compatible chat-completions
endpoint or a local Transformers client. The policy receives
`Task.policy_view()` only. The prompt template requires exactly one terminal
action per generation:

```text
<think>...</think><search>query</search>
<think>...</think><visit>doc_id</visit>
<think>...</think><answer>final answer</answer>
```

`parse_policy_output()` rejects missing, malformed, unterminated, empty, or
multiple action tags. Raw model text and actual response token IDs are retained
in `PolicyOutput` and semantic step metadata. A training run configured with
`require_token_ids=True` stops if the backend does not return actual sampled
IDs; it never decodes and re-tokenizes generated text.

## Dataset and retrieval

`NQTaskAdapter` converts a Natural Questions-style JSONL row into an evaluator
`Task`. It records upstream name/revision, split, preprocessing version,
selected IDs, and a deterministic data hash. `policy_metadata` is an explicit
allow-list; answer aliases and evidence IDs are not exposed to the policy.
The repository contains only `data/m1/dev.jsonl`, a three-row CI fixture.

`HTTPRetriever` is a generic POST adapter for `/search` and `/visit/{doc_id}`.
It returns stable `Evidence` IDs, deterministic ranks, backend/version
metadata, timeout and HTTP error classification, and no Oracle fallback. The
M0 BM25 environment remains the deterministic test backend.

## M1-B exact token provenance

Each actual model call produces a `GenerationRecord` containing:

- exact `prompt_ids` supplied after `apply_chat_template` and tokenization;
- exact `response_ids` returned by generation;
- one `response_logprobs` value per response ID for the local model;
- prompt messages, model/checkpoint, tokenizer/template versions, sampling
  configuration, sampling seed, finish reason, and a prompt fingerprint.

`TrainingTrace.generation_records` is the canonical multi-turn representation.
It is intentionally turn-wise: a later prompt contains chat-template role
tokens, prior assistant turns, and tool observations. The trace refuses to
expose a fake flattened `input_ids` sequence for multi-turn records.
Tool observation IDs are retained as explicit zero-loss spans; assistant
response IDs have mask 1 and a valid `step_index`. OpenAI-compatible backends
may provide response IDs, but prompt IDs remain unavailable unless the backend
actually returns them, so such rollouts cannot be converted to the local
training-ready trace silently.

For the local Qwen2.5 client, old log-probabilities are gathered from the model
logits at the exact positions of the generated response IDs:

```text
log π_old(y_t | prompt_ids, y_<t)
```

The scorer receives integer IDs directly, performs no sampling and no decode /
re-tokenize round trip. Environment tokens never receive policy log-probability
loss.

## Training projection and reward

`TrainingTrace` is separate from semantic `Trajectory`. It stores exact
generation records, response IDs, step mapping, old log-probabilities, reward
components, and sampling metadata. `TokenTurn` requires integer IDs supplied by
the model boundary. Policy-generated assistant tokens receive
`response_mask=1`; tool observations receive `0`; system and user prompt tokens
are outside the response projection and are zero in `full_response_mask` for
the legacy single-sequence representation.

M1 reward is rule-based final-answer correctness with deterministic normalized
exact match. `RewardBreakdown` records `answer_correct`, `format_valid`, and
`total`. Missing or malformed/no-answer rollouts receive zero. There is no
process reward, judge, search-depth bonus, or fatal-aware shaping.

## Group rollouts and vanilla GRPO

`run_group_rollouts()` requests a fixed group size, preserves `sample_index` and
`rollout_id`, and records failed/cancelled slots rather than dropping them.
Group mean, population standard deviation, and zero-variance status include
missing slots as zero reward. `compute_group_advantages()` normalizes outcome
rewards within each group.

The default `grpo_loss()` reduction is per response sequence:

```text
L_i = sum_t(mask_it * token_objective_it) / max(sum_t(mask_it), 1)
L   = mean(L_i over sequences with at least one active token)
```

Thus a 20-token response does not receive ten times the weight of a 2-token
response. `old_logprobs` are behavior-policy probabilities for the importance
ratio. `reference_logprobs` is a separate optional input for KL; setting
`kl_coef > 0` without it raises an error. The evaluator's
`group_exact_match_variance` remains distinct from the trainer's
`group_reward_variance`.

`rllm_adapter.py` is deliberately thin: it converts TraceSearch tasks,
episodes, and reward outputs while leaving rLLM/verl internals external. This
checkout has no compatibility-tested `rllm`/`verl` installation, so Level C is
blocked and no training result is reported.

## Group diagnostics and Level-B dry run

`run_group_rollouts()` records per-group reward mean/std, zero-variance,
all-zero/all-one rates, unique action sequences, unique final answers, mean
trajectory length, and mean generated-token count. The Level-B command persists
these diagnostics before any optimizer exists:

```bash
python -m tracesearch.cli.run_m1_rollout \
  --dataset data/m1/dev.jsonl \
  --corpus data/m0/corpus.jsonl \
  --model-path E:\\MinimaxH3\\models\\Qwen2.5-3B-Instruct \
  --group-size 2 \
  --temperature 0.7 \
  --output runs/m1-level-b-rollout
```

The output contains `manifest.json`, `trajectories.jsonl`,
`generation_records.jsonl`, `training_traces.jsonl`, `reward_breakdown.jsonl`,
`group_diagnostics.json`, `metrics.json`, and `summary.md`. Missing slots have
zero reward and an explicit `trace: null` row. The command prints
`optimizer_steps: 0` and does not claim training.

## Baselines and commands

The controlled baseline policies are Direct Answer, Retrieve-once, and
Prompted Multi-turn Agent. They share the same dataset, model endpoint,
retriever, prompt protocol, and tool budget when run through `run_m1_eval`.

```bash
python -m tracesearch.cli.run_m1_eval \
  --dataset data/m1/dev.jsonl \
  --corpus data/m0/corpus.jsonl \
  --model-path E:\\MinimaxH3\\models\\Qwen2.5-3B-Instruct \
  --mode agent \
  --output runs/m1-agent
```

This formal local longitudinal smoke uses the explicit M0 BM25 corpus and the
local Qwen2.5-3B-Instruct checkpoint. The Qwen3.5-2B checkpoint was only used
for an exploratory smoke and is not part of the comparison because its local
generation showed unstable thinking/protocol behavior. A real external-service
run replaces `--corpus` with `--retriever-url`, and replaces `--model-path`
with `--base-url` plus `--model`.

The repository environment is a project-root `.venv` managed by `uv`. On the
current RTX 4090 machine, CUDA PyTorch is installed separately from the cu128
index after syncing the Python dependencies; the checkpoint itself remains an
external local model directory.

For a bounded real-data preparation run, keep the source dataset outside Git
and use the deterministic selector:

```bash
python -m tracesearch.cli.prepare_m1_data \
  --input /path/to/nq-style.jsonl \
  --output-dir data/local/m1 \
  --upstream-revision REVISION_OR_SNAPSHOT \
  --seed 42 --train-size 1000 --dev-size 200 --test-size 200
```

The command writes canonical split JSONL files and a provenance manifest with
stable IDs, answer aliases, revision, selection seed, and hashes. Gold answers
and evidence stay on evaluator-side `Task`; `Task.policy_view()` exposes only
the allow-listed policy surface. A Wikipedia retrieval snapshot/service is
still an explicit dependency and is not bundled here.

`run_m1_train` refuses to claim Level C when `rllm` or `verl` is absent. A
real-model Level-B smoke must show one search, one observation, final answer,
actual response IDs, aligned old log-probabilities, masked observations, and
training-ready generation records. Level C must additionally show a real model
weight/checkpoint change after an optimizer step. Neither is fabricated by the
CI fixture.

## Explicit M1 non-goals

M1 does not implement fatal-aware masking, contribution weighting, process
reward, LLM judges, adaptive search, retriever training, memory, multimodal
tools, OCR, live production Web deployment, or distributed GRPO training.
