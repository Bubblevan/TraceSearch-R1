# TraceSearch-R1 M1

M1 introduces the first learned-policy boundary without changing the
framework-neutral TraceSearch `Task`, `Action`, `ToolResult`, `Step`, or
`Trajectory` objects. The current implementation is the Level-A substrate;
it does not claim a real model rollout or a GRPO optimization result until the
required external services and training backend are available.

## Learned text policy

`LLMPolicy` uses `ModelClient` and an OpenAI-compatible chat-completions
endpoint. The policy receives `Task.policy_view()` only. The prompt template
requires exactly one terminal action per generation:

```text
<think>...</think><search>query</search>
<think>...</think><visit>doc_id</visit>
<think>...</think><answer>final answer</answer>
```

`parse_policy_output()` rejects missing, malformed, unterminated, empty, or
multiple action tags. Raw model text and the gateway's actual response token
IDs are retained in `PolicyOutput` and the semantic step metadata. A training
run configured with `require_token_ids=True` stops if the gateway does not
return actual sampled IDs; it never decodes and re-tokenizes generated text.

## Dataset and retrieval

`NQTaskAdapter` converts a Natural Questions-style JSONL row into an evaluator
`Task`. It records upstream name/revision, split, preprocessing version,
selected IDs, and a deterministic data hash. `policy_metadata` is an explicit
allow-list; answer aliases and evidence IDs are not exposed to the policy.
The repository contains only `data/m1/dev.jsonl`, a three-row CI fixture.

`HTTPRetriever` is a generic POST adapter for `/search` and `/visit/{doc_id}`.
It returns stable `Evidence` IDs, deterministic ranks, backend/version
metadata, timeout and HTTP error classification, and no Oracle fallback. The
M0 BM25 environment remains the deterministic test backend.

## Training projection and reward

`TrainingTrace` is separate from semantic `Trajectory`. It stores prompt IDs,
response IDs, step mapping, old log-probabilities, reward components, and
sampling metadata. `TokenTurn` requires integer IDs supplied by the model
gateway. Policy-generated assistant tokens receive `response_mask=1`; tool
observations receive `0`; system and user prompt tokens are outside the
response projection and are also zero in `full_response_mask`.

M1 reward is rule-based final-answer correctness with deterministic normalized
exact match. `RewardBreakdown` records `answer_correct`, `format_valid`, and
`total`. Missing or malformed/no-answer rollouts receive zero. There is no
process reward, judge, search-depth bonus, or fatal-aware shaping.

## Group rollouts and vanilla GRPO

`run_group_rollouts()` requests a fixed group size, preserves `sample_index` and
`rollout_id`, and records failed/cancelled slots rather than dropping them.
Group mean, population standard deviation, and zero-variance status include
missing slots as zero reward. `compute_group_advantages()` and `grpo_loss()`
implement the vanilla normalized group outcome objective over masked policy
tokens. The evaluator's `group_exact_match_variance` remains distinct from the
trainer's `group_reward_variance`.

`rllm_adapter.py` is deliberately thin: it converts TraceSearch tasks,
episodes, and reward outputs while leaving rLLM/verl internals external. The
optional `train` extra only provides PyTorch for the objective tests; this
checkout has no compatibility-tested `rllm`/`verl` installation, so Level C is
blocked and no training result is reported.

## Baselines and commands

The controlled baseline policies are Direct Answer, Retrieve-once, and
Prompted Multi-turn Agent. They share the same dataset, model endpoint,
retriever, prompt protocol, and tool budget when run through
`run_m1_eval`.

```bash
python -m tracesearch.cli.run_m1_eval \
  --dataset data/m1/dev.jsonl \
  --corpus data/m0/corpus.jsonl \
  --model-path E:\\MinimaxH3\\models\\Qwen2.5-3B-Instruct \
  --mode agent \
  --output runs/m1-agent
```

This formal local longitudinal smoke uses the explicit M0 BM25 corpus and the
local Qwen2.5-3B-Instruct checkpoint. The Qwen3.5-2B checkpoint was only used
for an exploratory smoke and is not part of the comparison because its local
generation showed unstable thinking/protocol behavior. A real external-service
run replaces `--corpus` with
`--retriever-url`, and replaces `--model-path` with `--base-url` plus `--model`.

The repository environment is a project-root `.venv` managed by `uv`. On the
current RTX 4090 machine, CUDA PyTorch is installed separately from the cu128
index after syncing the Python dependencies; the checkpoint itself remains an
external local model directory.

`run_m1_train` refuses to claim Level C when `rllm` or `verl` is absent. A
real-model Level-B smoke must show one search, one observation, final answer,
actual response IDs, masked observations, and trajectory artifacts. Level C
must additionally show a real model weight/checkpoint change after an optimizer
step. Neither is fabricated by the CI fixture.

## Explicit M1 non-goals

M1 does not implement fatal-aware masking, contribution weighting, process
reward, LLM judges, adaptive search, retriever training, memory, multimodal
tools, OCR, or live production Web deployment.
