# TraceSearch-R1 M0

M0 is the reproducible research substrate for later Agentic RL and credit
assignment work. It separates task data, policy decisions, environment
responses, stored trajectories, and evaluation artifacts so later trainers do
not need to reinterpret opaque logs.

## Core representation

- `Task` contains the question, answer aliases, split, and evaluation-only
  gold evidence IDs.
- `Action` is one of `search`, `visit`, or `answer`.
- `ToolResult` records the tool name, request, success state, structured
  evidence, text, latency, error type, and metadata.
- `Step` joins policy reasoning and an action with the structured tool result.
- `Trajectory` records a task run, termination reason, seed, and derived tool
  counters. Its JSONL form is the shared boundary for future training stages.

Gold evidence is not included in model-facing observations. The explicitly
named `OracleFixturePolicy` is used only by the fixture smoke runner to make
the environment integration answer all fixture tasks; it is not a learned
policy or a benchmark result.

## Aligned local environment

`data/m0/corpus.jsonl` and `data/m0/tasks.jsonl` form a small synthetic aligned
fixture. Every gold ID exists in the corpus, and the fixture includes single-
hop, genuine two-hop, and no-search calibration tasks. `BM25Index` uses
Unicode word tokenization, the standard transparent BM25 score, and
`(-score, doc_id)` tie-breaking. `visit` returns the complete aligned
document; unknown IDs produce `NOT_FOUND`.

## Fault taxonomy and determinism

Policy formatting errors, invalid arguments, execution failures, timeouts,
empty results, malformed results, and semantically irrelevant results are
stored distinctly. `FaultSchedule` targets an exact task/step/tool position.
`FailureInjector` uses a seeded `random.Random` with a fixed draw order.
Irrelevant-result injection is a successful call with semantic-corruption
metadata, not a tool execution error.

Given the same task, corpus hash, environment settings, fault settings,
policy, and seed, scripted execution produces the same decisions and
structured content. Measured wall-clock latency is diagnostic and may differ
between runs; the configured environment can be used where fixed latency is
needed.

## Artifacts and CLI

```text
runs/<run_id>/
  manifest.json
  trajectories.jsonl
  metrics.json
  summary.md
```

Install the package, then run:

```bash
python -m tracesearch.cli.run_m0 --seed 42 --top-k 5 --output runs/m0-smoke
python -m tracesearch.cli.run_m0 --fault-profile reproducible --seed 42 --output runs/m0-faults
```

The manifest includes the corpus SHA-256 hash, backend, seed, fault
configuration, policy/budgets, and nullable future model/training fields.
Metrics are recomputable from tasks and `trajectories.jsonl` alone. The
summary is generated from `metrics.json`, not from hand-written expected
numbers.

## Explicit non-goals

M0 does not implement transformers inference, SFT, GRPO, PPO, verl, rLLM,
vLLM, Ray rollout, contribution judging, self-play, retriever training,
memory, image tools, web APIs, or production deployment. It also makes no RL
performance claim.
